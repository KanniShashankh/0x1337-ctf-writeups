# Netlist Reverse

- **Category:** Reverse / Hardware
- **Points:** Level 1 special
- **Author:** john doe
- **Flag:** `0x1337{ECE>CSE}`
- **Files:** [`files/netlist_reverse.zip`](files/netlist_reverse.zip), [`solve.py`](solve.py)

## Challenge

> Decode the Netlist find the input which unlocks the module, your input is your key

The zip contains `netlist.v`, an anonymous gate-level Verilog netlist generated by Yosys, and `instructions.md`. The module `lock_core(clk, rst, data_in[7:0], valid, unlocked)` reads 15 bytes serially. A byte is sampled on each rising clock edge while `valid=1`, after a reset pulse. `unlocked` goes high only if all 15 bytes match the secret, and those bytes are the ASCII flag.

## Solution

1. **Map the netlist.** It contains about 360 single-bit `assign` gates (`~ & | ^`) and three registers:
   - `_332_[16:0]`: a one-hot FSM. `_332_[0]` is the idle state after reset. Each of the next states compares the incoming byte with constants built into the gates. `_332_[1]` is a sink state: any wrong byte sends the FSM there, and it stays until reset.
   - `_334_[31:0]`: a 32-bit shift register with XOR feedback. Its reset value is hardcoded, and each accepted byte is XORed into it.
   - `unlocked`: set from the last FSM state (`_332_[8]`) only when `_283_` is true. `_283_` checks the final byte together with the expected value of `_334_`.
2. **Simulate rather than reverse by hand.** No iverilog, Verilator or Yosys was installed, so `solve.py` parses the netlist into Python. Each `assign` becomes an expression over a dict of signal values. Combinational logic is evaluated by repeating passes until nothing changes. The `always @(posedge clk)` flops are handled with their synchronous reset and enable.
3. **Byte-by-byte search.** Reset, then try all 256 values for the next byte and keep each value that does not send the FSM to the sink state `_332_[1]`. A greedy pass is not enough. The per-state checks only look at some bits, so some positions accept more than one byte (for example, `'0'` and `'5'` at byte 0, `'t'` and `'x'` at byte 1). A false branch then fails a few bytes later. A depth-first search handles this and checks `unlocked` after the 15th byte. Only one sequence unlocks the module:

```
$ python3 solve.py netlist.v
0x1337{ECE>CSE}
```

The search runs in about 1.4 s. The 15 bytes already include the `0x1337{}` wrapper, so the key is also the flag.

## Lessons

- For a gate-level lock, simulation is usually faster than reconstructing the logic. A small Python evaluator is enough when no HDL tools are installed.
- One-hot FSM with a sink state: watch the sink bit to reject a wrong byte immediately. The search then grows with the number of positions instead of exponentially.
- Per-state checks can be partial, with the full check delayed (here, the shift register compared at the end). Use DFS or backtracking, not a greedy search.
